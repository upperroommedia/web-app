  <files>functions/src/DocumentListeners/Series/seriesItemOnWrite.ts, functions/src/index.ts, pages/admin/series/[seriesId].tsx, pages/admin/sermons/[sermonId].tsx, components/ManagePublishingPopup.tsx</files>
  <action>
    Introduce a canonical recalculation path for series metadata driven by `seriesItems` state.

    Implementation specifics:
    - Add a Firestore document listener for `series/{seriesId}/seriesItems/{itemId}` writes.
    - On every write, recompute:
      - `itemCount` = total seriesItems docs
      - `publishedItemCount` = seriesItems where `publishedToSubsplash === true`
      - `subtitle` = `${publishedItemCount} part series`
      - `updatedAt` timestamp
    - Export listener in `functions/src/index.ts`.
    - Update publish/unpublish flows to keep `publishedToSubsplash` accurate:
      - Publish to series sets `publishedToSubsplash: true` and stores `sermonSubsplashId`.
      - Unpublish/delete-from-Subsplash path sets `publishedToSubsplash: false` and clears stale subsplash linkage for that series item.
    - Remove manual `itemCount` mutations in client code where they can conflict with canonical listener updates, or keep as optimistic-only with eventual listener reconciliation.

    Safety:
    - Use idempotent updates and avoid listener loops (write only series doc; trigger source is seriesItems).
    - Ensure missing/deleted sermon edge cases do not break series metadata updates.
  </action>
  <verify>
    - `rg -n "seriesItemOnWrite|publishedItemCount|part series" functions/src`
    - Simulate local flow: add/remove/publish/unpublish item and confirm series doc subtitle reflects published count only.
  </verify>
  <done>
    Series subtitle and published counts are derived from current seriesItems state and remain correct across publish-state transitions.
  </done>
