# Firestore → Algolia function kit

Local, Apache-2.0 fork of [Algolia's Firestore search extension](https://github.com/algolia/firestore-algolia-search), upstream version 1.3.0, commit `8b2c5183a90cf440c031a676a13bd9fc05d761dd`. The original extension currently has no publisher-provided kit. This implements Firebase's [self-created kit migration](https://firebase.google.com/docs/extensions/users/migrate-self-created) and [publisher migration guide](https://firebase.google.com/docs/extensions/publishers/migrate).

The Firebase CLI installs this package once and creates separate configuration directories for each index instance. `FIREBASE_KIT_INSTANCE_ID` comes from the CLI; do not define it manually in deployed config. Functions deploy as `kit-<instance>-executeIndexOperation` and `kit-<instance>-executeFullIndexOperation`.

## Configuration

Export the existing instance using `firebase ext:export --mode functions --instance <extension-id> --kit-instance <kit-id> --project <project>`. Preserve the secret reference generated by the CLI, including its existing secret name; never commit API key values.

| Parameter | Behavior |
| --- | --- |
| `COLLECTION_PATH` | Existing collection path; supports wildcard collection-group paths |
| `DATABASE_ID` | Firestore database, defaults to `(default)` |
| `LOCATION` | Function region, defaults to `us-central1`; keep near Firestore |
| `ALGOLIA_APP_ID` | Existing Algolia application |
| `ALGOLIA_INDEX_NAME` | Existing Algolia index |
| `ALGOLIA_API_KEY` | Required secret with object save and delete permissions |
| `FIELDS` | Optional comma/space-separated field selection, including nested paths |
| `ALT_OBJECT_ID` | Optional string field or `(path)`, otherwise document ID |
| `TRANSFORM_FUNCTION` | Optional existing callable HTTP transformation function name |
| `DO_FULL_INDEXING` | `true` enables backfill after first deploy and redeploy |
| `FORCE_DATA_SYNC` | Accepted for export compatibility; all writes read current state |

CLI-exported `EXT_MIGRATED_SYSTEM_*` settings are translated into both handlers: memory, minimum/maximum instances, timeout, VPC connector and egress, ingress, CPU, concurrency, JSON labels and runtime service account. `FUNCTION_DEFAULT_REGION` is supported as a shared default; the original `LOCATION` parameter explicitly places these two handlers. Exported settings take precedence over kit defaults of 512MiB/zero minimum instances, live-handler 180-second timeout/20 maximum instances, and backfill 540-second timeout/two maximum instances. Unspecified ingress/egress enum sentinels are omitted. This applies per-handler settings without overwriting the generated instance wrapper's global options.

Both handlers bind `ALGOLIA_API_KEY` explicitly. Transforms receive the same `{data: record}` request and return `{result: record}` response as the extension. A failed transform rejects for retry; document identity is retained even if a transform returns another ID.

## IAM, lifecycle, and billing

The code declares `firestore.googleapis.com`, `cloudtasks.googleapis.com`, and roles `datastore.user`, `cloudtasks.enqueuer`, and `run.invoker`. Firebase grants them to the kit's managed service account. The CLI also provisions event delivery permissions. All functions within this instance share these permissions.

`afterFirstDeploy` and `afterRedeploy` enqueue `executeFullIndexOperation`. To repeat a failed backfill: `firebase functions:lifecycle:run afterFirstDeploy <kit-id> --project <project>`. Pages contain 25 documents, process five documents concurrently, and advance only after every document succeeds. Document-ID cursors survive deletion of the previous page's final document.

Source reads and `_algoliaSyncLocks` metadata writes incur Firestore charges in addition to Cloud Functions, Cloud Tasks and Algolia costs. The private metadata collection stores one small record per indexed source document and kit instance, including its last Algolia ID and a lease. It must not be readable or writable by clients. Metadata is retained after source deletion to remove stale alternate IDs on later retries. A terminated worker's lease expires after ten minutes; queued retries then recover.

## Robustness changes

The legacy extension swallowed indexing failures, allowing missing records to persist. This kit propagates failures and enables event retries. It serializes writes per document, reads the latest source, waits for the Algolia indexing task, and rereads source versions to reconcile concurrent updates. Delayed deletion events therefore preserve a recreated document; full indexing uses the same path as live indexing. Each write replaces the complete selected/transformed record, removing attributes deleted from Firestore. Alternate object ID changes remove the previous record.

Run `npm test` in this directory. Tests cover serialization, selected fields, transforms, source reordering, deletion/recreation, alternate ID changes, indexing failures, overlapping execution and full-index pagination. Actual Firestore transactions and deployed Eventarc delivery additionally require staging verification; do not remove the old extension before validating kit-specific logs.
