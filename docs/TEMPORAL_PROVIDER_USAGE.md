# Provider references and safe retirement

Provider cleanup uses a private authoritative reverse index rather than scanning an arbitrary number of sermons. Each project/provider/account/remote ID has an epoch aggregate with an exact reference count and one edge per canonical document, immutable active job intent, or external binding reservation. Shared Subsplash IDs conservatively share one resource namespace across resource types. Subsplash is scoped to app key `9XTSHD`; SoundCloud uses the deployment's configured account and live ownership verification. Project isolation does not establish exclusive ownership of a provider asset shared outside the application.

`prepareProviderUsageChanges` reads all aggregates and edges before any transaction writes and returns one write-only callback. Pass all canonical changes in a transaction together, including membership mirrors. This prevents lost counts when several documents reference the same resource. Public atomic increment transforms also preserve counts when admission prepares an immutable intent and a canonical document in separate helpers within the same transaction. Canonical writers and cleanup claims contend on the same aggregate. An index disagreement fails closed.

External association requests must first commit `prepareProviderBinding`. The association edge survives unknown responses and worker restarts. Release it only after the remote association is proved removed or the same reference has been recorded durably in canonical documents. Removing an active intent edge at terminal job state never releases an unresolved external binding edge. Orphan review can retire only its exact derived pending child binding: verified absence requires zero references after subtracting that single edge, while retention replaces it atomically with the permanent original-resource edge.

`prepareProviderCleanupClaim` verifies the actual private provider receipt, exact job/project/fingerprint/revision/remote ID, and zero authoritative references before reserving cleanup. Any canonical association or external binding to a reserved resource fails. Reservations have no expiry: a lost DELETE acknowledgement requires a fresh remote GET or operator reconciliation. Only proved absence permits the permanent deleted tombstone. Explicit reviewed retention can reopen the matching reservation; it cannot claim the earlier DELETE succeeded.

An adopted existing resource is always retained by automatic cancellation, even with no local references. Selecting an existing compatible asset is not evidence of exclusive ownership or the original POST's outcome. The unknown original allocation remains a review item. Any separate administrator deletion requires its own canonical and external association proof.

## Initial cutover

Use `scripts/temporal-backfill-provider-usage.mjs` after all provider writers have legacy ownership, admission has been paused, legacy tasks and invocations have drained, and the release controller has recorded the matching drain witness. Run without `--apply` first; dry run does not write an index or readiness marker.

```
node scripts/temporal-backfill-provider-usage.mjs \
  --project urm-app-staging --release RELEASE_UUID \
  --control-revision REVISION --drain-proof DRAIN_PROOF_FILE
```

The controller can repeat this command with `--apply`. The drain proof contains `schemaVersion: 1`, exact project/release/control revision, `result: "passed"`, and `legacyDrained: true`. The command rejects emulator environment variables and verifies real private control and unresolved legacy invocation leases. Media, publishing, images, and accounts domains must be paused with legacy ownership. Search need not change ownership.

The command pages through all canonical roots, membership collection groups, and private nonterminal job intents, and immutable original-acknowledgement review records and exact same-ID administrator retention records, image resource retention records, authenticated image allocation acknowledgement facts, and original provider acknowledgement facts. Unreviewed provider orphan acknowledgements restore their exact temporary child review binding; reviewed acknowledgements require their matching immutable disposition seal. Original provider account proof stays separate from the stable index account alias. Pending additional image acknowledgements restore the exact temporary child binding. A cleaned child requires a sealed authenticated fixed-ID absence proof tied to the original provider account; a retained child requires its validated permanent retention ledger. Raw acknowledgements do not become permanent retention edges. Image retentions compare the immutable audit with the sealed reviewed/retained image receipt; their original pre-review receipt fingerprint is compared with the audit rather than the changed post-review receipt. Same-ID retentions revalidate the confirmed provider receipt, unchanged resource, sealed cleanup review, actor, command, fingerprint, and revision before restoring their permanent binding edge. Retained reviews restore the permanent orphan binding edge in a new epoch; verified cleanup reviews restore the original resource tombstone and reject conflicting references. Every source document is re-read in the transaction and compared against its scanned update time. A building epoch is promoted to ready only after all pages finish under the same frozen release control. There is no fleet size ceiling. A failed run leaves the index unavailable. Rerunning under the same frozen release and revision resumes the same building epoch from its last committed page cursor. Partial pages are safely repeated because each edge insertion is idempotent. Page checkpoints compare their previous group and cursor transactionally, so concurrent operators cannot advance a stale checkpoint. Readiness requires all fifteen groups to have completed. Source-certified legacy SoundCloud retention restores its permanent owner edge only after validating the original immutable certificate, initial no-SEND observation, intent and explicit administrator grant. The retained track remains protected after its source job completes or its sermon is removed; the unverified read never becomes an absence tombstone. The legacy admission barrier must prohibit new provider continuations once this release's index is building or ready.

The release controller verifies `_control/temporalProviderUsage` project, schema, ready state, epoch, release ID, and the recorded backfill revision before ownership transfer. Later release control revisions do not change the witness's original backfill revision. Upgrading an already-running Temporal deployment preserves its existing index and reservations rather than rebuilding around active work.
